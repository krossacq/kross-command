# Kross Command Snapshot Purpose

Kross Command exists so Tax Mogul Bureau has a repeatable way to build and support Kross Agent environments.

The goal is not to make Kross Command a tax office assistant.

The goal is to make Kross Command the internal bureau-level operator that can help Sydne:

- prepare firm VM environments
- install Hermes/Kross Agent
- copy the correct Kross Agent snapshot into the firm VM
- configure firm-specific workspaces
- track model provider access rules
- document launch readiness
- troubleshoot agent/server issues
- prepare future automation for firm onboarding

## Why Kross Command Needs Its Own Repo

Kross Agent and Kross Command have different jobs.

Keeping a separate repo prevents:

- Kross Command instructions from being baked into firm-level Kross Agent behavior
- firm-level Kross Agent SOPs from being confused with bureau infrastructure SOPs
- Returns and Revenue Office pilot work from becoming undocumented one-off setup
- future firm deployments from relying on memory instead of repeatable runbooks
